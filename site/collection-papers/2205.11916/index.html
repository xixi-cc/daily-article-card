Large Language Models are Zero-Shot Reasoners

大型语言模型是零样本推理器

Paper Collection · Prompting and Reasoning · 原文

Card 02 研究问题

研究问题

  • Few-shot chain-of-thought 需要为每个任务手写推理示例。作者问：不提供任何示例，只在问题后加入同一个“Let's think step by step”提示，是否能让大语言模型先生成推理过程，再通过第二个答案抽取提示得到最终答案？
  • 研究检验的是提示引发的输出与基准准确率，不证明生成的自然语言链是模型内部真实因果计算或逻辑上始终忠实。
Card 03 模型与方法

模型与方法

  • Zero-shot-CoT 是两阶段 prompting：第一阶段在问题后附加 task-agnostic rationale prompt，生成逐步文本；第二阶段把问题、生成链和格式相关 answer prompt 重新输入模型，抽取数值、选项或短答案。标准 zero-shot 使用同样答案抽取框架但不先生成 CoT。
  • 主实验用 text-davinci-002/InstructGPT，并在 GPT-3 与 540B PaLM 等模型上做补充。12 个数据集分为算术（SingleEq、AddSub、MultiArith、GSM8K、AQUA-RAT、SVAMP）、常识（CommonsenseQA、StrategyQA）、符号（Last Letter、Coin Flip）与 BIG-bench 逻辑任务。
  • 作者比较不同 rationale wording、模型规模、答案 prompt，并与 zero-shot、few-shot 与 Few-shot-CoT 基线对照。温度/解码、prompt 文本、模型 API 版本和答案解析规则都是结果组成部分。
Card 04 核心结果与证据

核心结果与证据

  • text-davinci-002 上，MultiArith 从标准 zero-shot 的 17.7% 提升到 78.7%，GSM8K 从 10.4% 提升到 40.7%；AQUA、SVAMP、符号与其他逻辑任务也普遍提升。SingleEq/AddSub 本来较偏单步，收益较小或持平。
  • Figure 1 用同一算术题展示：标准 zero-shot 直接给错答案，Zero-shot-CoT 在没有示例时生成多步过程并得到正确答案。跨任务使用同一句提示是方法的主要简洁性，但 Table 1 同时显示答案抽取模板可改变数值。
  • 较大模型的收益更明显，PaLM 复现实验支持现象不只属于一个 API；不过论文比较的是当时的封闭模型快照，不能自动外推到后续指令微调、工具增强或安全过滤后的模型。
Card 05 有效性与局限

有效性与局限

  • 准确率依赖 prompt 措辞、答案抽取、解码和 API 版本；两阶段调用增加 token/计算成本。基准可能存在训练数据污染，论文没有对预训练语料做审计。生成链可能包含错误步骤却碰巧给出正确答案，也可能暴露不忠实 rationalization。
  • 12 个基准以短答案为主，距离开放世界规划、科学推理和可验证证明仍远。论文标题中的“reasoners”应读为这些任务上的行为性能力；结果不证明一般推理、认知机制或可靠性。当前模型生态已变化，历史数值需要在固定旧模型或明确新模型上重新测量。
