Interpretable Machine Learning for Science with PySR and SymbolicRegression.jl

用 PySR 与 SymbolicRegression.jl 做可解释科学机器学习

PySR is an open-source library for practical symbolic regression, a type of machine learning which aims to discover human-interpretable symbolic models. PySR was developed to democratize and popularize symbolic regression for the sciences, and is built on a high-performance distributed back-end, a flexible search algorithm, and interfaces with several deep learning packages. PySR's internal search algorithm is a multi-population evolutionary algorithm, which consists of a unique evolve-simplify-optimize loop, designed for optimization of unknown scalar constants in newly-discovered empirical expressions. PySR's backend is the extremely optimized Julia library SymbolicRegression.jl, which can be used directly from Julia. Paper Collection · Machine Learning · 原文

PySR 是面向科学方程发现的开源 symbolic regression 工具；Python 前端连接高性能 Julia 后端 SymbolicRegression.jl，以多种群进化搜索表达式的误差—复杂度 Pareto 前沿。 核心循环是 evolve–simplify–optimize：结构突变后做代数化简，再用 BFGS 等数值优化新表达式中的实常数。 论文还提出九条历史经验定律组成的 EmpiricalBench，要求算法在噪声、真实量纲范围和未知非整数常数下恢复函数形式。

摘要

  • PySR 是面向科学方程发现的开源 symbolic regression 工具；Python 前端连接高性能 Julia 后端 SymbolicRegression.jl，以多种群进化搜索表达式的误差—复杂度 Pareto 前沿。

Card 03 背景

背景

  • symbolic regression 不只追求预测误差，还要在可解释复杂度上做多目标选择；科学用户通常需要一组 Pareto 候选，而非单一黑盒最优式。
  • 常见 Feynman/Nguyen 合成 benchmark 往往直接给定物理常数、使用规整采样和简单噪声；这与历史上从不完美观测中同时发现结构和常数的任务有距离。
  • PySR 的设计强调自定义算符、量纲/复杂度约束、非光滑表达式、并行种群与深度学习接口，目标是可用的软件而非只在一个合成表上得分。
Card 04 模型与方法

模型与方法

  • 每个种群维护表达式树，锦标赛选择后执行节点/算符变异或 crossover；模拟退火式接受准则允许暂时变差，migration 在种群间传递候选，hall of fame 保存每个复杂度的最佳式（Figs. 1–4, Algorithms 1–4）。
  • 默认复杂度统计运算节点、变量和常数，但用户可按领域设定；自适应 parsimony 根据种群中各复杂度频率调整惩罚，避免搜索只停在简单或庞大表达式。
  • EmpiricalBench 含 Hubble、Kepler、Newton、Planck、Leavitt、Schechter、Bode、ideal gas、Rydberg 九条定律；原数据可得时直接使用或从原图表数字化，否则按现实变量范围生成并加噪。
  • 六种方法各对九个任务跑 5 次，每次最多 1 小时、8 个 AMD Rome CPU cores；整条 Pareto front 由人工判断 correct/almost/failed/incorrect。
Card 05 核心结果与证据

核心结果与证据

  • Table 3 中 PySR 在 Hubble、Kepler、Newton、Leavitt、Schechter、Bode、ideal gas 七项均为 5/5 correct，在 Planck 与 Rydberg 为 0/5，总计 35/45。
  • DSR 在 Kepler 4/5、Leavitt/Schechter/ideal gas 各 5/5，但有多项 failed；Operon 只有 Newton 1/5、Schechter 5/5、Bode 3/5。EQL 与 SR-Transformer 没有 correct trial，QLattice 仅 Schechter 5/5。
  • 作者把 crash、domain error 和未定义表达式计入失败，强调软件稳定性是科学可用性的一部分；但也承认作者更熟悉 PySR 环境，可能让它获得配置与稳定性优势。
  • 所有方法都未恢复 Planck 与 Rydberg，说明复杂指数/倒数结构与实常数仍是共同难点；结果不是“PySR 可发现任意物理定律”。
Card 06 有效性与局限

有效性与局限

  • benchmark 只有九条定律、每项五次，人工目检允许忽略小常数误差；没有独立盲评或置信区间，算法排序对任务和配置敏感。
  • 全部数据用于训练，因为评价对象是表达式本身；因此结果衡量结构恢复，不衡量留出集泛化。
  • 一小时/8-core 预算没有逐算法调优；作者团队对自家软件更熟悉，其他包的 crash 或配置失败不一定代表其最佳能力。
  • EmpiricalBench 不统计函数评估次数、搜索能耗或数值预测精度，也混合原始与合成数据；35/45 是该协议下的结构恢复计数。

Card 08 阅读指南

阅读指南

  • 先看 Figs. 3–4 理解内外循环，再看 Section 2 的 simplify/constant optimization/adaptive parsimony；这些是 PySR 与朴素遗传编程的主要差异。
  • 随后读 Fig. 5、Tables 2–3，把每个 5-run 分解中的 failed 与 incorrect 分开，不要只看总正确数。
  • 实际使用时先定义允许算符与复杂度，再检查量纲、稳定性和外推；Pareto front 上的简洁式仍需物理验证。
