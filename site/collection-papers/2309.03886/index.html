FIND: A Function Description Benchmark for Evaluating Interpretability Methods

作者信息

Card 02 研究问题

研究问题

  • 自动可解释性系统开始让语言模型为神经网络单元或模块写自然语言描述，但真实模型通常没有唯一、完备的 ground truth，因而很难判断描述究竟正确还是只听起来合理。FIND 试图先在已知函数上拆解这个评价问题。
  • 核心问题不是‘LM 能否解释任意网络’，而是：给解释器黑盒查询权限后，它能否恢复函数的全局规律、局部例外、噪声和组合结构，并用可执行代码或可检验语言准确表达？
Card 03 模型与方法

模型与方法

  • FIND 程序化生成 2000 余个函数解释任务，覆盖数值函数、字符串操作、实体/关系映射和由 Vicuna 模拟的 synthetic neural modules。复杂性通过函数组合、缩放/偏置、近似、噪声及局部 domain corruption 引入；结构在生成时已知。
  • 解释器可得到固定 exemplars（non-interactive）、自主选择输入查询黑盒函数（Automated Interpretability Agent, AIA），或先看 exemplars 再交互。AIA 被提示形成假设、设计实验并根据输出更新描述，实验比较 GPT-4、GPT-3.5、Llama-2 等 off-the-shelf LMs。
  • 代码描述按测试集执行：数值函数用 normalized MSE，阈值 NMSE<0.1；字符串可用 exact match。自然语言描述通过 LM evaluator 的三选一 input-output unit test 评分。这种 protocol 可扩展，但 evaluator 本身是模型，且三选一只测试描述能否区分所给 distractors。
Card 04 核心结果与证据

核心结果与证据

  • Table 2 显示 GPT-4 AIA 在各函数类别上普遍优于 GPT-3.5 与 Llama-2；摘要同时指出最佳方法也只描述约 48% 的函数。论文观察到 Llama-2 有时不调用函数便编造输出，说明 agent interface 本身不保证有效实验。
  • 交互并非一概优于固定 exemplars：AIA 能主动寻找 informative inputs、识别部分组合和例外，但初始化 exemplars 的收益取决于函数类别。Figure 3 展示成功的假设—实验—修正轨迹，Figure 4 与附录也保留失败和只拟合全局趋势而漏掉局部 corruption 的案例。
  • 自然语言 unit test 分数常高于生成代码的精确执行分数，因为宽泛但不够具体的描述仍可能选对代表性 I/O。结果支持把 FIND 当作解释器能力诊断台，而不是把某个自动解释系统认证为适用于真实模型。
Card 05 有效性与局限

有效性与局限

  • 程序化函数提供明确 ground truth，却仍是代理任务：单一黑盒函数的可识别性与大模型中分布式、上下文依赖的子计算不同。Vicuna 模拟的 neural modules 还引入生成模型随机性与提示依赖。
  • unit-test evaluator 可能受描述措辞、distractor 难度和 evaluator 模型偏差影响；三选一 chance level 为 1/3，不能等同于精确语义恢复。数值 NMSE 的区间、测试点和 0.1 阈值也决定结论，局部窄异常可能被平均误差掩盖。
  • 比较混合了 base model 能力、agent 提示、查询预算和工具使用纪律；更长交互不自动意味着更好科学推理。论文没有证明自动描述能解释真实神经网络的因果机制，结论应限定为所构造 FIND 任务上的 baseline。
