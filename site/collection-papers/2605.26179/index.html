AutoDFT: A Closed-Loop Multi-Agent Framework for Autonomous DFT Calculations

AutoDFT：面向第一性原理计算的闭环多智能体执行与恢复

Card 02 研究问题

研究问题

  • 真实 DFT 工作流不是一次性写好 INCAR 后等待结束：SCF 不收敛、磁态或金属性交替、结构对称性破缺、\(k\)-point 不足以及中间物理发现都会迫使研究者改参数或改计划。论文问：LLM agent 能否在每一步读取 VASP 证据、恢复失败并重排后续计算，而不只生成开环脚本？
  • AutoDFT 把自动化目标定义为端到端任务成功和可用物性，而不是“输入文件能生成”或“VASP 进程退出为零”。
Card 03 背景

背景

  • DFT 的可靠性来自电子结构问题、数值离散和工作流因果链共同闭合。以表面 spin-PDOS 为例，slab relaxation、磁性 SCF、CHGCAR 复用、NSCF、\(k\)-point refinement 与最终投影态密度相互依赖；早期错误会在后续产生看似平滑但物理错误的谱。
  • 开环 agent 在规划时一次性固定全部参数，后续仅用规则恢复。AutoDFT 采用 skeletal plan：先规定每步目标和成功条件，具体数值参数到执行前才结合 history 决定。
Card 04 模型与方法

模型与方法

  • 系统协调七类角色：Strategic Planner 维护高层步骤，Step Planner 生成即时 VASP 输入，rule-based executor 提交任务，Dual-Path Monitor 结合解析规则与 LLM 判断输出，Recoverer 修复失败，Reflector 根据新物理证据修改计划，Property Extractor 读取最终量。
  • 每步循环保存输入、stdout/文件、monitor verdict、恢复尝试和结构化 history。失败不是无限重试：恢复器针对 charge sloshing、CHGCAR 不兼容、离子步或对称性等诊断生成有限修改，reflector 只有在结果改变后续目标时才重写计划。
  • 评价含 VASPBench 的 34 个官方文档任务、9 类计算，以及 Materials Project 的 20 个材料子集；比较 full closed loop、open-loop planning 与 rule-based baseline，并跨 GPT-5.2、Claude Sonnet 4.6、Gemini 3.1 Pro Preview。
Card 05 核心结果与证据

核心结果与证据

  • Figure 1 用 Ni(100) slab 展示闭环为何必要：开环方案把表面当 bulk-like 3D、遗漏磁性、错误复用 charge density 并在 PDOS 前失败；闭环检测金属性/磁性、重做 SCF 与 CHGCAR、发现近 Fermi 能带峰后细化 \(k\)-mesh，最终得到层分辨 spin-PDOS。
  • VASPBench 上 GPT-5.2 full system 成功 32/\(34=94.1\)%，open-loop 28/\(34=82.4\)%，rule-based 23/\(34=67.6\)%。最大增益出现在 phonon DFPT（full 100%，rule 0%，open 50%）和 molecular dynamics 等多阶段任务。
  • 20-material 评估给出 band gap、magnetic moment 和 formation energy 相对 Materials Project PBE 的 MAE；但 Table 2 只在成功完成且提取到预测的任务上计算，各 backbone 的 \(n\) 不同，因此 MAE 必须与 completion rate 一起读。
  • Table 3 的 counterfactual audit 统计成功任务是否实际使用 LLM recovery、monitor termination 或 plan modification，支持闭环组件参与了部分成功；它仍是基于执行日志的归因，不是逐任务随机消融。
Card 06 有效性与局限

有效性与局限

  • 34 个 VASPBench 任务规模小且源自官方文档，任务分布、成功判据与允许工具由作者设计；94.1% 不能外推为任意材料、任意赝势、任意 HPC 环境的自治率。
  • Materials Project 比较使用 PBE reference，并只统计成功预测，存在可用样本选择效应；数据库数值也不是实验真值。不同赝势、U、磁初态和结构弛豫约定会产生系统差异。
  • LLM backbone 与版本会变化，恢复决策可能非确定；复现必须保留 prompts、工具输出、VASP 版本、POTCAR provenance、随机性与完整失败轨迹。高成功率也不等于无人监督即可安全开展高代价计算。
  • 该卡核对全文、流程图、表格和案例；no independent reproduction performed，未运行 VASPBench、VASP 或 Materials Project 对照。
