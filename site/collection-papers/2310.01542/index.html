Fusing Models with Complementary Expertise

融合具有互补专长的模型

Card 02 研究问题

研究问题

  • 多个 expert 各自擅长不同 domain 时，简单平均会把不懂当前样本的模型也纳入；最大置信度又可能被 OOD 过度自信欺骗。论文问能否只用少量跨域 validation data，学习一个输出层 fuser，组合互补知识而不重新训练所有 experts。
  • 对昂贵 LLM，另一个问题是每个输入调用全部 experts 的成本。FrugalFoE 进一步要求在性能和 expert-query 数量之间显式权衡。
Card 03 模型与方法

模型与方法

  • 假设测试分布是 \(K\) 个 subdomains 的 mixture，并已有每域 expert。分类任务把所有 expert probability vectors 拼接，训练小型 Fθ 预测标签；生成任务则拼接各 expert 对输入/输出的 last-layer token embeddings，训练 fuser 选择最合适的 expert，而非训练一个新的生成 LLM。
  • FoE 的监督信号来自各 domain validation sets，因此实际学到的是 expert-output pattern 到标签/域的映射。论文还分析何时互补性、expert domain skill 和 fuser error 足以让 FoE 优于单 expert 或 ensemble。
  • FrugalFoE 用阈值判断是否继续查询 expert，并把 sequential expert-selection 写成带性能—成本目标的决策问题；实现用 validation data 估计转移/收益，论文给出 graph shortest-path 解释。
Card 04 核心结果与证据

核心结果与证据

  • 实验覆盖 CIFAR-100 super-class、sentiment classification、跨域 summarization、MMLU multiple-choice QA 和生成文本自动评价。表 1–5 中 FoE 通常优于平均、confidence selection 和单 experts，说明学习的 fuser 能利用互补输出。
  • CIFAR-100 使用 20 个重叠子类 experts；FrugalFoE 在该设置中查询约 37.5% experts 即达到调用全部 20 个 FoE 的 accuracy。这个比例来自特定 \(\kappa\)、\(M\)、\(\lambda\) 和 expert 顺序，不是通用成本定律。
  • 生成任务通过 expert embedding 做 routing，避免 tokenizer/vocabulary 必须一致；自动评价实验比较融合指标与人类标签相关性。不同任务使用不同 expert family、validation size 和 metric，不能把所有提升合并为单一 scaling 结论。
Card 05 有效性与局限

有效性与局限

  • 方法需要每个 domain 的有标签 validation data，且验证分布须覆盖部署 mixture；新 domain、label shift 或 expert 更新会使 fuser 失配。所谓 domain agnostic 指模型形式，不代表免除 domain coverage 假设。
  • 拼接所有 expert 输出的标准 FoE 仍需全量推理，内存和延迟随 \(K\) 增长。FrugalFoE 降低平均查询数，但 routing 本身、expert warm-up、并发和 tail latency 均会影响真实成本。
  • 对生成模型，选择一个 expert 不等于融合其知识；last-layer embedding 跨架构维度、tokenization 和 calibration 的可比性需要工程处理。实验提升也可能部分来自 fuser 学习 dataset/domain identity，而非可迁移的语义专长。
