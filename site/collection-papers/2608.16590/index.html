Zetta $ζ$: An Efficient Closed-Loop Embodied Harness for Self-Evolving Physical Intelligence

Zetta：用于具身智能自演化的闭环 Harness

Embodied agents are increasingly used to close the gap left by end-to-end policy models. Yet the agentic path has not realized closed-loop learning in physical execution: existing harnesses remain largely open-loop, following fixed skills during rollout and reflecting only after an episode completes. Such post-hoc reflection cannot govern execution as it unfolds, because physical interaction requires decisions to track rapidly changing robot-environment states at a frequency beyond today's large agentic models. We present Zetta, a closed-loop embodied harness that evolves code-based runtime critics and recovery skills online while keeping the base policy frozen. Through three timescale-separated loops, Zetta provides action-frequency governance, rollout-level critic-recovery proposal, and validation-gated skill updates. Card 03 背景

背景

  • 论证节点“端到端 VLA 与事后反思之间缺少执行中的治理层”。
  • VLA/WAM 扩大模型与示范数据，但部署分布变化使固定策略脆弱。
  • 既有 embodied agent 常在 episode 后反思；执行时仍沿固定 skill 或预规划轨迹，无法跟踪快速变化的接触与抓取状态。
  • Zetta 保持 base policy 冻结，把可演化部分放在代码化 critic、recovery skill 与验证门控的 harness。
  • 让高频运行时治理与低频大模型反思分离，避免要求 agentic model 在每个控制周期决策。
  • Zetta 针对具身 agent 仅事后反思、执行中开环的缺口，并保持基础策略冻结 （\(p\). 3; source/tex/\(arxiv_{\mathrm{submission}}\)/tex/introduction.tex）
  • 研究问题的表述以论文给出的对象和评价目标为边界；背景动机不自动构成方法有效性的证据。
Card 04 模型与方法

模型与方法

  • 论证节点“三个时间尺度分别负责动作、rollout 与能力更新”。
  • 动作频率运行时 critic 读取当前状态，在已有 recovery 范围内触发、抑制或切换，不等待大模型重新规划。
  • Rollout 频率对失败轨迹做机制聚类与层级因果诊断，生成 critic--recovery 候选。
  • 演化频率候选必须通过闭环验证、回归与推广条件，才进入累计 harness；基础 VLA 保持冻结。
  • 方法以在线治理、rollout 诊断和验证门控更新构成三阶段闭环 （\(p\). 7; source/tex/\(arxiv_{\mathrm{submission}}\)/tex/method.tex）

Card 05 核心结果与证据

核心结果与证据

  • 2：在线 rollout 由固定动作策略与可演化 harness 协作；失败经聚类、因果诊断、critic--recovery 提案和验证后，才合并为可复用能力。
  • 证据解释：Zetta 把“发现失败—提出修复—同条件验证—推广复用”做成有权限边界的闭环，而不是直接改 VLA 权重。
  • Zetta 的在线执行、离线演化和验证门控整体架构 （\(p\). 5; figure Figure 2; source/tex/\(arxiv_{\mathrm{submission}}\)/tex/method.tex）
  • 论证节点“提案、离线通过与环境成功必须分层记账”。
  • Critic 只报告当前风险与候选干预；它的接受不等于动作已执行。
  • Recovery 必须在相同失败机制和固定预算下验证，并检查是否引入新失败。
  • 只有环境终止条件确认的任务完成，才计入成功率；累计版本还需保留此前有效能力。
  • 因此所谓“自演化”发生在 harness 代码与技能库，不是在线更新基础模型参数。
  • 论文规定 critic-guided repair 的验证、成功判据和能力推广流程 （\(p\). 10; source/tex/\(arxiv_{\mathrm{submission}}\)/tex/method.tex）
  • 6：RoboCasa 18 个任务上的累计版本从冻结 parent harness 出发，逐轮加入经验证的全局修复；论文报告 macro-average 由 $73.56\%$ 提升到 $93.56\%$。
  • 证据解释：作者把提升归因于累计 critic--recovery 能力；该曲线是论文协议下的内部累计评测，不应脱离 seed、预算和 success 定义单独解读。
  • 论文报告 RoboCasa 累计 harness 的宏平均成功率由 73.56% 增至 93.56% （\(p\). 24; figure Figure 6; source/tex/\(arxiv_{\mathrm{submission}}\)/tex/experiment.tex）
  • 论证节点“论文报告成功率、迁移与吞吐三类结果”。
  • 在当前 rollout budget 下，作者报告 LIBERO-Pro $90.8\%$、RoboCasa $93.6\%$。
  • Goal-\(T\)/Goal-S 与 RoboCasa 曲线展示累计能力、跨任务零样本迁移和若干“故障前沿后移”案例。
