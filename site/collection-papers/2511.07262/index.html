AgenticSciML: Collaborative Multi-Agent Systems for Emergent Discovery in Scientific Machine Learning

AgenticSciML：用于科学机器学习涌现式发现的协作多智能体系统

Scientific Machine Learning (SciML) integrates data-driven inference with physical modeling to solve complex problems in science and engineering. However, the design of SciML architectures, loss formulations, and training strategies remains an expert-driven research process, requiring extensive experimentation and problem-specific insights. Here we introduce AgenticSciML, a collaborative multi-agent system in which over 10 specialized AI agents collaborate to propose, critique, and refine SciML solutions through structured reasoning and iterative evolution. The framework integrates structured debate, retrieval-augmented method memory, and ensemble-guided evolutionary search, enabling the agents to generate and assess new hypotheses about architectures and optimization procedures. Paper Collection · AI for Science · 原文

AgenticSciML 用十余种角色完成数据分析、评价合同、单 agent 根解、知识检索、proposal–critic 四轮辩论、代码实现/调试、数值评价和多模型 selector voting。 六个问题覆盖不连续函数拟合、L-shaped Poisson PINN、Burgers PINN、反导数 operator、多输入 reaction-diffusion operator 与稀疏含噪 cylinder-wake 重建。 冠军相对单次 root engineer 的 error 改善从 10× 到 11169×；这是同一框架内 root/champion 比，不是与穷尽的人类专家或公平算力基线的统一比较。

摘要

Card 03 背景

背景

  • SciML 的架构、loss、采样和优化常需领域专家反复实验。传统 AutoML/NAS 多在预定义搜索空间调参，而该系统让 LLM 对问题结构和训练失败提出可执行的方案修改。
  • 用户提供 Problem、Requirements、Evaluation 与可选 Data；evaluator 生成固定 eval.py/guidelines 后必须由人批准，避免搜索中改动评分规则。
  • knowledge base 含论文、摘要、方法与代码片段；retriever 每个 parent 最多提供一条相关记录，persistent analysis base 保存 parent/sibling/uncle 的数值与图像诊断。
Card 04 模型与方法

模型与方法

  • 每轮总是扩展当前最好解，同时由 Gemini-2.5-pro、GPT-5-mini、Grok-4-fast selector ensemble 投票选探索 parents；每个 parent 经 4-round proposer–critic debate，engineer 只按最终 proposal 修改父代码，debugger 修到可执行或达到上限。
  • champion 是固定 evaluator 下最小 score 的树节点；单 agent root 无 knowledge base、debate 或 tree search，因此 multi-agent 后续既获得更多 LLM calls，也获得多次 GPU training/evaluation。
  • 六项分别使用 MSE 或 relative \(L_{2}\) error；全部运行于 NVIDIA \(A_{6000}\)。主文报告用户文字少于 0.3%，但工程/selector 的 word count 被排除，所以该比例不是人类工时或总系统信息量。
  • KB ablation 只在不连续函数任务控制：相同 root/evaluator/agents、6 iterations、batch size 4，比较 70-entry Full KB、No KB 与 Random KB。
Card 05 核心结果与证据

核心结果与证据

  • \(root\to champion\) 数值为：函数拟合 MSE \(0.283\to 1.46\)×10^-3（194×）；\(L\)-shaped Poisson \(0.0332\to 3.58\)×10^-5（约927×）；Burgers \(0.0449\to 4.02\)×10^-6（11169×）。
  • 反导数 operator relative \(L_{2}\) 为 \(0.810\to 0.00121\)（约669×）；multi-input operator 为 \(0.137\to 0.00878\)（约15.6×）；cylinder wake 为 \(0.238\to 0.0232\)（约10.3×）。任务和指标不同，倍率不能直接比较科学难度。
  • 冠军策略包含 sigmoid-gated MoE、known-particular-solution+corner importance sampling、三阶段 gPINN/RAR/\(L\)-BFGS、linear bias-free DeepONet branch、derivative-enhanced FNO 与 CNO-style bandlimit filter；Table 1 显示这些组合不逐字出现在检索条目。
  • KB ablation 的共同 root \(\mathrm{MSE}=0.2828776240\)；Full/No/Random KB 最佳分别为 0.0014631104、0.0034207932、0.0303153563。No-KB 仍大幅改善，Random KB 则比 Full 高 20.720×，支持检索相关性影响搜索轨迹，但证据只有一个任务。
  • 每项 LLM API 成本 $2.07–$11.30；训练常是时间瓶颈，例如 Poisson GPU 5.6h vs LLM 1.7h，multi-input 10.7h vs 2.1h。成本没有计入研究设计、人类审核、知识库整理和硬件折旧。
Card 06 有效性与局限

有效性与局限

  • 每题主要展示一次 evolutionary run 的最好节点；大倍率可能受较弱 root、试验次数和 winner selection 影响，缺少多 seed 分布与等算力 random/AutoML/search baseline。
  • “不在 KB”只排除了 70-entry curated memory 的直接文本，不证明策略在完整文献中原创；许多冠军是已知组件的组合与问题特化。
  • agent debate 的文字合理性仍由 LLM 产生，真正约束来自 fixed numerical evaluator；若 evaluator 与科学目标错位，搜索可优化错误代理。
  • 评价成本随 tree expansion 增长，真实 multiphysics、turbulence、data assimilation 和实验流程尚未验证；knowledge base 覆盖与 retrieval grounding 也是显式局限。
