Transformers Struggle to Learn to Search

Transformer 难以学会搜索

Card 02 研究问题

研究问题

  • 给定图的边与 start/goal，判断是否存在路径是基本搜索问题；Transformer 在海量样本下能否学习可扩展算法，而非记住短路径或分布频率？
  • 训练分布若大量包含易例/负例，会否使梯度忽略需要长 lookahead 的稀有例？即便训练准确率收敛，内部是否形成层层合并 reachability 的算法，且能否外推更大图？
Card 03 模型与方法

模型与方法

  • 输入序列编码 DAG edges、start 和 goal，label 是 reachability；同一问题也翻译成 implicational propositional logic 的自然语言 proof search。Figure 1 展示图与序列/证明对应。
  • 比较 naïve、star 与按 lookahead 难度平衡的训练分布；模型最多见到 8.83 亿 examples。测试按图大小、路径长度和 held-out 分布分层。
  • 机制分析用干预/探针重建每个输入的 computation graph，寻找 exponential path-merging：每层 token 合并更长可达关系，理论上深度带来指数扩张的搜索范围。
Card 04 核心结果与证据

核心结果与证据

  • naïve 分布训练即便样本极多也难以稳定解决长 lookahead；平衡困难例显著改善，但仍有 seed 不收敛或测试失败。Figure 2 展示训练分布对 accuracy 的巨大影响。
  • 在成功模型中，重建 computation graph 常识别到 path-merging operations；Figure 5 比较训练模型与随机控制，并统计 maximal merges。机制出现与搜索泛化相关，但不是每个成功样本都给出清晰同一电路。
  • 随最大图大小增加，最低 test loss 恶化、收敛 seed 比例下降；扩大模型和数据不能简单消除难度。论文因此强调当前 Transformer 对系统搜索的 sample inefficiency 与优化困难。
Card 05 有效性与局限

有效性与局限

  • 任务是随机 DAG reachability，输入编码和 label 形式固定；真实搜索可借助 scratchpad、chain-of-thought、tool use 或 recurrent computation，这些超出一次前向分类设置。
  • 平衡分布使用任务难度先验，改善可能来自 curriculum 而非模型自行发现通用搜索。机制重建依赖阈值与局部解释，path merging 的因果必要性需更强 ablation。
  • 标题“struggle”是相对于样本量、图规模与成功率的经验结论，不表示 Transformer 形式上不能实现搜索算法。本卡未独立复现。
