CodePDE: An Inference Framework for LLM-driven PDE Solver Generation

CodePDE：面向 LLM 驱动 PDE 求解器生成的推理框架

Card 01 作者信息

作者信息

  • 作者为 Shanda Li、Tanya Marwah、Junhong Shen、Weiwei Sun、Andrej Risteski、Yiming Yang 与 Ameet Talwalkar；PDF 首页列出 Carnegie Mellon University、Flatiron Institute、Polymathic AI 与 Datadog。核对版本为 arXiv:2505.08783v2，且首页标注 TMLR 2026 年 2 月发表。论文把 PDE 数值求解的实现过程交给 LLM 生成 Python solver，并评估推理时的调试、改进和采样，而非训练一个新的 neural operator。
Card 02 研究问题

研究问题

  • 给定方程、区域、初始/边界条件，LLM 能否写出可执行且数值正确的 PDE solver？作者进一步把问题拆成四种可区分能力：数值方案推理、运行报错后的自调试、依据误差反馈的 refinement，以及 best-of-\(n\) 推理预算扩张。关键标准不是代码是否看似合理，而是能否运行、nRMSE、效率与经验收敛率。
  • 这是 AI for physics 的工作：物理对象仍是 Advection、Burgers、Reaction-Diffusion、compressible Navier--Stokes 和 Darcy flow；LLM 的输出是离散算法。它并不声称生成程序替代已验证的生产求解器，尤其在硬 PDE、边界条件和稳定性上仍须独立数值审计。
Card 03 背景

背景

  • 本文把一般 PDE 写作 $\mathcal Lu(\tilde x)=\varphi(\tilde x)$ 于 $\Omega$、$\mathcal Bu(\tilde x)=\psi(\tilde x)$ 于边界。数值求解的真实负载包括空间离散、时间积分、稳定步长和边界实现；这些结构使“能输出代码”与“求得正确解”不同。CodePDE 要求模型从自然语言任务中提出多样方案，再让运行反馈参与选择（\(p\). 4）。
  • 评测抽取 PDEBench 与 FNO 数据，五类 PDE 各采样 100 个实例，比较 16 个 LLM、传统手工/软件求解器、神经求解器及 FunSearch、AIDE 等 agent 工作流。主要误差是 normalized RMSE；还单列 debug success、收敛测试、执行时间和所选数值方案（\(p\). 5）。
Card 04 模型与方法

模型与方法

  • CodePDE 的五步链条为任务 specification、chain-of-thought code generation、执行与错误反馈、迭代 code repair、基于评估的 refinement/best-of-\(n\) 选择（Figure 1, \(p\). 3；Method, pp. 4--5）。调试把报错 trace、原任务与失败代码回传给 LLM，直到修复或达到预设次数；这只保证运行层面的修正，不能自动保证离散误差小。
  • 质量指标为 $\mathrm{nRMSE}=S^{-1}\sum_s\|u^{(s)}-\hat u^{(s)}\|_2/\|u^{(s)}\|_2$。此外作者在固定网格下拟合经验 convergence order，并统计 solver library、空间 scheme 与时间积分的分布，故可以区分“低误差但保守”的 solver 与“探索多样方案但易失败”的 solver（pp. 5, 8--10）。
Card 05 核心结果与证据

核心结果与证据

  • Figure 2（\(p\). 8）是最直接的可运行性证据：五类 PDE 和各 LLM 的平均 bug-free rate 均在 self-debug 后提高，总平均从 41% 升至 84%；例如 CNS 从 16.6% 到 66.6%，Burgers 从 46.9% 到 92.2%。图只报告代码能完成执行/修复的比例，不等价于误差或稳定性保证。
  • 表 1（\(p\). 7）比较 nRMSE，作者报告 self-refinement 在测试 PDE 上持续改善解质量；Figure 3（\(p\). 8）显示 best-of-\(n\) 增加时代表模型的平滑 test-time scaling 曲线改善。论文也发现 reasoning model 在“reasoning+debugging”阶段常更强，却不一定在 refinement 超过 GPT-4o/DeepSeek-\(V_{3}\)，说明 code generation 与 feedback-driven improvement 可能是不同能力。
  • Figure 4 与 Table 2（pp. 9--10）补上数值学边界：经验收敛率和失败率随 PDE/模型而异；在 Claude-3.7-sonnet 的 ablation 中，debugging、refinement 和 best-of-\(n\) 是框架的重要组成。该证据来自有限 benchmark 实例和作者实现，不能替代对每个生成 solver 的网格加密、守恒和边界残差验证。
Card 06 有效性与局限

有效性与局限

  • 评测只覆盖五个 PDE family、指定参数分布、Python 环境和 100-instance 样本；nRMSE 依赖参考解与归一化约定。复杂多物理、刚性、非规则几何或真实工业边界条件的适用性未由这些统计直接证明。论文自己强调 hard tasks 的 failure modes，并发现可靠性与方案 sophistication 有 trade-off（pp. 9--11）。
  • 自调试可将 crash 转为可运行代码，但错误离散、错误边界条件或不稳定积分可能仍产生貌似平滑的错误解。经验 convergence rate 也不是解析收敛证明。LLM/API 版本、随机采样、库版本和 timeout 都会改变 best-of-\(n\) 结果，因此“test-time scaling”应读作本协议下的经验趋势。
